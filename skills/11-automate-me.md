# automate-me：把你的习惯变成 skill（Grok Bot 版）

来源：pstack v0.15.36 `skills/automate-me/SKILL.md`。
原版挖 Cursor 的 `agent-transcripts/` 对话记录。本版没有对话记录可挖，改成挖仓库历史（git log、PR 记录、review 评论）加上直接问你。流程本身不变。

## 什么时候用

“按我的方式干活”“把我的偏好写进 skill”“给我做一个我自己的 -mode”。

任务型的 skill（只做一件事的流程）不要走这套，直接写一个 skill 文件。

## 流程

### 0. 先查有没有现成的

找仓库里已有的 `*-mode` skill（`AGENTS.md` 或 `skills/` 下）。有就确认意图：更新现有（默认）还是从头写（少见，先问为什么）。

更新模式：只挖 skill 上次被改之后的历史，保留没被推翻的章节，只改有新证据的。

### 1. 挖历史

看最近几周的仓库历史，找重复出现的模式：

- 回应偏好（长度、语气、格式、“说人话”式纠正）
- 分派习惯（并行、模型分工、专用流程）
- 验证姿态（“做完”是什么意思、单元测试还是真实复现、谁评审）
- 代码与文字纪律（风格、引用的原则、lint 与格式化工具）
- 流程习惯（worktree、commit、PR、评审与合入工具）
- 元偏好（中途修 skill、主动提议新 skill）

两个以上地方都出现的模式是高置信。只出现一次的通常是噪音，丢掉。

### 2. 直接问你

挖掘漏掉还没发生过的意图。用选择题问，不要让人从头打字。一到两个问题，每题 4 到 6 个选项。先问大类（哪些方面重要），再按选中的追问细节。最后留一个自由问题收尾。

问题不要超过 20 个。

### 3. 聚类

把挖到的与问到的分组。只用贴得上的组：

- 回应风格：长度、语气、格式。
- 自主程度：多少事不用问、能用什么工具。
- 先搞懂：接手改动时先找哪些 skill。
- 分工：默认分派、并行、模型与任务匹配。
- 文字与代码纪律：原则、lint、风格。
- 评审与验证：复现姿态、验证技能、真实测试工具。
- 流程：worktree、commit、PR、评审与合入。
- skill 习惯：写 skill 的习惯、中途修 skill、提议新 skill。

参考 `00-poteto-mode.md` 的粒度。不要抄它的内容。你的规则与它不一样。

### 4. 起草

写成 `skills/<你的名字>-mode.md`。正文开头写清触发条件（你的名字 + 工作风格）。一句话说明。

### 5. 改文字

按 AGENTS.md 的回复规则过一遍每一行。拿草稿给用户看，收反馈。预计多轮。狠狠地删。mode skill 不是手册。

### 6. 落地

放进仓库，单独一个 commit 与 PR。不要直接推 main。

## 护栏

- 不要对一次对话过拟合。说了一次、别处又推翻的偏好是噪音。出现多次才写进去。
- 不要耍聪明。复述别的 skill、编比喻、给 agent 读者写“诗意”文字都是成本，没有收益。保持可操作。
- 引用，不要全文贴。别的 skill 出现时写路径，不要粘贴摘录。
- 章节最小化。没有具体、非默认的规则就不加这一节。“沟通清楚”不是一节。“短段落。比较用表格。真正并列才用 bullet。”是一节。
- 名字用通用的。“用户”或“人”，不要写作者的名字。
- 不要强求对称。某个方面没有值得写的规则就跳过。

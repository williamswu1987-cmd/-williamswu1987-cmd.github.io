# /correct（Grok Bot 版）

来源：pstack v0.15.36 `skills/correct/SKILL.md`。原文就是这套方法的说明书，本版只把 Cursor 的检查点换成仓库里能跑的东西。

用户一直在为同一类错误纠正 agent。改掉仓库，让下一个 agent 犯不了这个错。

前提：每个贡献者都是一个 agent。它只看自己打开的文件，抄最近的例子，走最短的能编译的路。把仓库设计成：从单个文件看是对的改动，对整个仓库也是对的。

## 找错的类别

先读最近的 commit、revert、评审意见、agent 指令文件，以及解释绕过办法的注释。把错误归类。一个类别出现两次才算数。

## 每类错往最高层修

1. **架构层消除**。每块状态只有一个 owner，每件事只有一种被支持的做法。藏起内部实现，让错误的 import 直接失败。把手工同步的列表换成单一事实来源。删掉 agent 会抄的旧路和死代码。
2. **类型层堵住**。坏代码还能编译时，加 lint 或 CI 检查，报错信息里点名该用的文件、类型或函数。如果这种写法已经很常见，只对新增的违规失败。
3. **测试行为**。修掉或删掉那种“行为坏了还绿、只改内部实现就红”的测试。
4. **文档或 agent 规则最后写**。只写给判断类问题。agent 跳过文档时什么都不会报错，所以文档永远是最后一道防线。

## 修好并证明

每次修最常见的类别，一次一个 commit。证明每个新检查会在一个真实的历史错误上失败。本地与 CI 跑同一条命令。例外写在出问题的那行，带理由、过期日期与人类批准。

## 维护规则表

在 agent 指令文件（本仓库的 `AGENTS.md`）里维护一张表，每条规则配上是什么在强制执行它。用户纠正你时，修掉错误并加规则。如果规则已经在了但没有任何东西在强制执行它，那就是一次重复，在同一次改动里往最高层修。错已经不可能发生时，删掉这条规则。

**回复**：每个类别、证据、选的层级、更高层级为什么行不通。
